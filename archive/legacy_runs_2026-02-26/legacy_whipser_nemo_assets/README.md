# 
Speaker Diarization pipeline based on OpenAI Whisper

<img src="https://github.blog/wp-content/uploads/2020/09/github-stars-logo_Color.png" alt="drawing" width="25"/> **Please, star the project on github (see top-right corner) if you appreciate my contribution to the community!**

## What is it
This repository combines Whisper ASR capabilities with Voice Activity Detection (VAD) and Speaker Embedding to identify the speaker for each sentence in the transcription generated by Whisper. First, the vocals are extracted from the audio to increase the speaker embedding accuracy, then the transcription is generated using Whisper, then the timestamps are corrected and aligned using `ctc-forced-aligner` to help minimize diarization error due to time shift. The audio is then passed into MarbleNet for VAD and segmentation to exclude silences, TitaNet is then used to extract speaker embeddings to identify the speaker for each segment, the result is then associated with the timestamps generated by `ctc-forced-aligner` to detect the speaker for each word based on timestamps and then realigned using punctuation models to compensate for minor time shifts.


Whisper and NeMo parameters are coded into diarize.py and helpers.py, I will add the CLI arguments to change them later
## Installation
Python >= `3.10` is needed, `3.9` will work but you'll need to manually install the requirements one by one.

`FFMPEG` and `Cython` are needed as prerequisites to install the requirements
```
pip install cython
```
or
```
sudo apt update && sudo apt install cython3
```
```
# on Ubuntu or Debian
sudo apt update && sudo apt install ffmpeg

# on Arch Linux
sudo pacman -S ffmpeg

# on MacOS using Homebrew (https://brew.sh/)
brew install ffmpeg

# on Windows using Chocolatey (https://chocolatey.org/)
choco install ffmpeg

# on Windows using Scoop (https://scoop.sh/)
scoop install ffmpeg

# on Windows using WinGet (https://github.com/microsoft/winget-cli)
winget install ffmpeg
```
```
# NeMo backend
pip install -c constraints.txt -r requirements_common.txt -r requirements_nemo.txt

# Pyannote backend
pip install -c constraints.txt -r requirements_common.txt -r requirements_pyannote.txt
```
## Usage 

```
python diarize.py -a AUDIO_FILE_NAME
```

By default, the script looks for audio in `../audio_in/` and writes outputs to `../job_outputs/manual_run/`.
You can omit `-a/--audio` to pick from a list of files in `../audio_in/`.
Outputs are written as `<audio_basename>.txt` and `<audio_basename>.srt` in the output directory.
By default, only diarization outputs are written (`.txt` and `.srt`).  
If needed, add `--save-whisper-input` to also copy `<audio_basename>_whisper_input.<ext>`.

Examples:
```
# Choose from ../audio_in/
python diarize.py

# Explicit input file (relative to ../audio_in/)
python diarize.py -a my_audio.wav

# Explicit path and custom output folder
python diarize.py -a /path/to/audio.wav --output-dir /path/to/outputs
```

If your system has enough VRAM (>=10GB), you can use `diarize_parallel.py` instead, the difference is that it runs NeMo in parallel with Whisper, this can be beneficial in some cases and the result is the same since the two models are nondependent on each other. This is still experimental, so expect errors and sharp edges. Your feedback is welcome.

## Command Line Options

- `-a AUDIO_FILE_NAME`: The name or path of the audio file to be processed (optional; prompts if omitted)
- `--input-dir`: Directory containing input audio files, default is `../audio_in`
- `--output-dir`: Directory to write diarized outputs, default is `../job_outputs/manual_run`
- `--no-stem`: Disables source separation
- `--whisper-model`: The model to be used for ASR, default is `medium.en`
- `--suppress_numerals`: Transcribes numbers in their pronounced letters instead of digits, improves alignment accuracy
- `--device`: Choose which device to use, defaults to "cuda" if available
- `--language`: Manually select language, useful if language detection failed
- `--batch-size`: Batch size for batched inference, reduce if you run out of memory, set to 0 for non-batched inference
- `--diarizer`: Diarization backend (`nemo` or `pyannote`; `msdd` kept as alias for `nemo`)
- `--hf-token`: Hugging Face token for gated pyannote pipeline access (or set `HF_TOKEN`)
- `--pyannote-pipeline-model`: Pipeline model id (default `pyannote/speaker-diarization-3.1`)
- `--pyannote-segmentation-model`: Segmentation model id (default `diarizers-community/speaker-segmentation-fine-tuned-callhome-zho`)
- `--save-whisper-input`: Optional; also copy `<audio_basename>_whisper_input.<ext>` into the output directory

## Known Limitations
- Overlapping speakers are yet to be addressed, a possible approach would be to separate the audio file and isolate only one speaker, then feed it into the pipeline but this will need much more computation
- There might be some errors, please raise an issue if you encounter any.

## Running on SCU WAVE (SLURM/GPU)
This setup now has one single-job entrypoint and one bulk-job entrypoint.

### Single diarization
Interactive submit (choose backend + choose file number):
```bash
cd /WAVE/users2/unix/<user>/SeniorDesign
./submit_single_diarization.sh
```

Non-interactive:
```bash
cd /WAVE/users2/unix/<user>/SeniorDesign
```

Outputs/logs:

- Step logs: `../job_logs/single_diarization_job_<JOBID>/`
- Slurm logs: `../job_logs/slurm/single_diarization_<JOBID>.out|err`

### Bulk diarization
Interactive submit (choose backend):
```bash
cd /WAVE/users2/unix/<user>/SeniorDesign
./submit_bulk_diarization.sh
```

Non-interactive:
```bash
cd /WAVE/users2/unix/<user>/SeniorDesign
sbatch --export=ALL,DIARIZATION_BACKEND="nemo" bulk_diarization.sbatch
```

Outputs/logs:
- Outputs: `../job_outputs/bulk_diarization/bulk_diarization_job_<JOBID>/`
- Step logs: `../job_logs/bulk_diarization_job_<JOBID>/`
- Slurm logs: `../job_logs/slurm/bulk_diarization_<JOBID>.out|err`

### Backend selection
- `DIARIZATION_BACKEND=nemo` uses NeMo MSDD (current default).
- `DIARIZATION_BACKEND=pyannote` uses pyannote pipeline plus custom segmentation model:
  `diarizers-community/speaker-segmentation-fine-tuned-callhome-zho`.

For pyannote, set a Hugging Face token before submit:
```bash
export HF_TOKEN="hf_xxx"
```
and ensure your account has access to `pyannote/speaker-diarization-3.1`.

## Downloading YouTube audio into `audio_in/`
Use `download_youtube.py` to pull a video’s audio straight to WAV (16 kHz mono) for testing.
```
# from repo root
python download_youtube.py https://www.youtube.com/watch?v=VIDEO_ID
```
By default files land in `../audio_in/` with the pattern `<title>_<id>.wav`. Change destination with `-o PATH` if needed. Requires `yt-dlp` and `ffmpeg` (installed via requirements and available on WAVE nodes). You can then run diarization on the downloaded file:
```
python diarize.py -a "<title>_<id>.wav"
```

## Bulk YouTube download + diarize
1. Add your links to `../youtube_links.txt` (one per line, `#` for comments).
2. Submit:
   ```bash
   sbatch /WAVE/users2/unix/<user>/SeniorDesign/bulk_diarization.sbatch
   ```
   Or choose backend interactively:
   ```bash
   cd /WAVE/users2/unix/<user>/SeniorDesign
   ./submit_bulk_diarization.sh
   ```
3. The job downloads all links to `../audio_in/`, then diarizes each file and writes results to `../job_outputs/bulk_diarization/bulk_diarization_job_<JOBID>/`.
4. Logs land in `~/SeniorDesign/job_logs/`:
   - Slurm stdout/stderr: `slurm/bulk_diarization_<JOBID>.out|err`
   - Step logs: `bulk_diarization_job_<JOBID>/`
   - Per-job output map: `bulk_diarization_job_<JOBID>/locations.tsv`
5. First run can be slow because the runtime venv installs large dependencies (PyTorch/CUDA/NeMo). Later runs are faster because installs are skipped unless `requirements_common.txt`, `requirements_nemo.txt` / `requirements_pyannote.txt`, or `constraints.txt` changes.
6. Per-run step logs are written under `~/SeniorDesign/job_logs/bulk_diarization_job_<JOBID>/`:
   - `download_*.out/.err` for each YouTube URL conversion
   - `diarize_*.out/.err` for each audio diarization run
   - `runtime_summary.tsv` with one line per audio and runtime seconds
7. URL-to-audio tracking table is stored at `~/SeniorDesign/sbatch_runtime/url_audio_index.tsv`:
   - `status=ok` means URL maps to a valid WAV in `audio_in/`
   - `status=failed` stores the error (for example, unavailable/private video)
   - if `audio_in` already has `*_<video_id>.wav`, conversion is skipped and that file is reused
   - previously downloaded URLs are skipped automatically and marked `skipped_existing` in each run’s `url_resolution.tsv`
   - failed URLs are automatically removed from `~/SeniorDesign/youtube_links.txt`
   - failed/removed URL reports are written to `~/SeniorDesign/youtube_links_err/` (`failed_links_<JOBID>.tsv` and `failed_links_latest.tsv`)
8. Bulk job uses the same speed defaults (`WHISPER_MODEL=small.en`, `WHISPER_BATCH_SIZE=16`) and supports override:
   ```bash
   WHISPER_MODEL=medium.en WHISPER_BATCH_SIZE=8 DIARIZATION_BACKEND=pyannote sbatch /WAVE/users2/unix/<user>/SeniorDesign/bulk_diarization.sbatch
   ```

## Troubleshooting on WAVE
- **Permission denied creating `/WAVE/scratch/…` caches**: The batch script now keeps model caches under `$HOME/.cache/huggingface` instead of `/WAVE/scratch`, which avoids scratch ACL issues.
- **`nemo_toolkit` / `faster_whisper` not found**: Ensure Python ≥3.10. The provided SLURM script loads `Python/3.12.3-GCCcore-14.2.0` before creating the venv so the correct wheels resolve.
- **Reset a broken environment**: Remove the venv(s) and temp/cache dirs, then resubmit:
  ```
  cd /WAVE/users2/unix/<user>/SeniorDesign/Whipser-Nemo
  rm -rf ../sbatch_runtime/.venv ../sbatch_runtime/.venv_pyannote ../sbatch_runtime/tmp
  sbatch ../single_diarization.sbatch
  ```
- Pip and HuggingFace caches are kept in `$HOME/.cache` (writable on WAVE). Temporary build files go to `../sbatch_runtime/tmp`.
- Pip is forced to PyPI (`PIP_INDEX_URL=https://pypi.org/simple`) with NVIDIA as extra index (`PIP_EXTRA_INDEX_URL=https://pypi.nvidia.com`) so newer `nemo_toolkit` wheels are visible.
- The batch script now uses a login shell (`#!/bin/bash -l`), exports `PIP_EXTRA_INDEX_URL=https://pypi.nvidia.com`, and installs with `--extra-index-url` so NeMo wheels are found.
- **No FFmpeg on WAVE**: Source separation (Demucs) requires ffmpeg/torchcodec. To keep jobs working, `--no-stem` is now default in `diarize.py`, and the SLURM scripts pass `--no-stem` explicitly.
- If you already created an old venv, remove it and resubmit: `rm -rf /WAVE/users2/unix/<user>/SeniorDesign/sbatch_runtime/.venv /WAVE/users2/unix/<user>/SeniorDesign/sbatch_runtime/.venv_pyannote && sbatch /WAVE/users2/unix/<user>/SeniorDesign/single_diarization.sbatch`.
